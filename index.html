      What this model does—and does not—say

      All operations start together. Retry layers execute sequentially and wait for children to exhaust their budgets. Fixed server processing time, an explicit response-loss window, and seeded backoff determine the timeline. Timed-out server work can finish later; mutation events are ordered by server completion.

      No network calls, load tests, chaos injection, billing, or agent execution occur. Per-layer independent deadlines, cancellation, queueing, rate limits, circuit breakers, variable latency and concurrent speculative retries are not modeled. Results are scenario estimates, not probability forecasts or an exactly-once guarantee.

      For real mutations, use an atomic server-side idempotency contract, stable keys tied to business intent, request fingerprint checks, suitable retention, and reconciliation for ambiguous outcomes.
